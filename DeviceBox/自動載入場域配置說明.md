# 自動載入場域配置功能說明

## 功能概述

系統現在會在以下兩個時機點自動從資料庫讀取並套用場域的最新配置：

1. **軟體啟動時** - 自動載入預設視圖(其他廠域)的最新配置
2. **切換場域時** - 點擊左上角切換按鈕時，自動載入切換後場域的最新配置

## 使用情境

### 情境 1：接續他人的工作
**問題**：A人員上午開啟軟體並在「其他廠域」設定為「模式一」，B人員下午開啟軟體，希望看到A人員設定的模式。

**解決方案**：
- B人員下午開啟軟體時，系統會自動從 `site_config` 資料庫讀取「其他廠域」的最新配置
- 軟體會自動套用 A人員設定的「模式一」
- 介面立即顯示正確的模式和排程

### 情境 2：在不同場域間切換
**問題**：軟體開啟時顯示「其他廠域」，切換到「鑄造廠域」時，希望看到該場域的最新配置。

**解決方案**：
- 點擊左上角場域切換按鈕
- 系統自動從資料庫讀取「鑄造廠域」的最新配置
- 介面自動套用該場域當前設定的模式
- 若切換回「其他廠域」，會再次讀取其最新配置

## 技術實作

### 資料來源
從 MySQL `site_config` 資料表讀取：
```sql
SELECT site_id, site_name, current_mode_id, config_data, 
	   config_version, last_updated_by, updated_at
FROM site_config
WHERE site_id = @siteId
```

### 載入時機

#### 1. 啟動時載入
```
MainForm 建構子
  ↓
InitializeViewBasedSync()
  ↓
LoadAndApplySiteConfig("other")  ← 載入其他廠域配置
  ↓
啟動同步服務
```

#### 2. 切換場域時載入
```
Factory_Click() - 使用者點擊切換按鈕
  ↓
切換 currentViewMode (OtherFactories ↔ CastingFactory)
  ↓
SwitchSyncSite()
  ↓
LoadAndApplySiteConfig("foundry" 或 "other")  ← 載入目標場域配置
  ↓
啟動新場域的同步服務
```

### 套用流程

`LoadAndApplySiteConfig(siteId)` 會執行以下步驟：

1. 從資料庫讀取場域配置 (`SiteConfig`)
2. 檢查是否有設定的模式 ID (`current_mode_id`)
3. 如果有，根據模式 ID 載入完整的模式資料 (`ScheduleMode`)
4. 套用模式：
   - 更新 `currentMode` 變數
   - 更新介面顯示 (label3, label4)
   - 設定 `isManualMode` 旗標
   - 套用模式的排程到設備配置
   - 重新載入配置 (`config.LoadConfig()`)
   - 刷新廠域顯示 (`RefreshFactoryDisplay()`)

## 資料庫驗證

### 查看場域配置
```sql
SELECT 
	site_id as '場域ID',
	site_name as '場域名稱',
	current_mode_id as '當前模式ID',
	config_version as '配置版本',
	last_updated_by as '最後更新者',
	updated_at as '更新時間'
FROM site_config
ORDER BY site_id;
```

### 測試場景

#### 設定其他廠域為模式一
```sql
UPDATE site_config
SET current_mode_id = 15,
	config_version = config_version + 1,
	last_updated_by = 'TestUser',
	updated_at = NOW()
WHERE site_id = 'other';
```

#### 設定鑄造廠為模式二
```sql
UPDATE site_config
SET current_mode_id = 20,
	config_version = config_version + 1,
	last_updated_by = 'TestUser',
	updated_at = NOW()
WHERE site_id = 'foundry';
```

## 測試步驟

### 測試 1：啟動時自動載入

1. **準備資料**：
   ```sql
   UPDATE site_config
   SET current_mode_id = 15,
	   last_updated_by = 'User_A',
	   updated_at = NOW()
   WHERE site_id = 'other';
   ```

2. **啟動軟體**：
   - 開啟 DeviceBox.exe
   - 觀察 label3 應顯示「模式一」(或對應的模式名稱)

3. **驗證日誌**：
   ```
   [MainForm] Loading site config from database for: other
   [MainForm] Applying mode: 模式一 (ID: 15)
   [MainForm] Site config applied successfully
   ```

### 測試 2：切換場域自動載入

1. **準備兩個場域的資料**：
   ```sql
   -- 其他廠域設為模式一
   UPDATE site_config
   SET current_mode_id = 15
   WHERE site_id = 'other';

   -- 鑄造廠設為模式二
   UPDATE site_config
   SET current_mode_id = 20
   WHERE site_id = 'foundry';
   ```

2. **測試流程**：
   - 啟動軟體 → 應顯示「模式一」(其他廠域)
   - 點擊左上角切換按鈕 → 應顯示「模式二」(鑄造廠)
   - 再次點擊切換 → 應回到「模式一」(其他廠域)

3. **驗證日誌**：
   每次切換應看到：
   ```
   [MainForm] Switching sync site to: foundry (CastingFactory)
   [MainForm] Loading site config from database for: foundry
   [MainForm] Applying mode: 模式二 (ID: 20)
   ```

### 測試 3：多人協作情境

**模擬 A 人員與 B 人員的工作流程**：

1. **A 人員上午工作**：
   - 開啟軟體 (其他廠域)
   - 切換模式到「模式一」
   - 關閉軟體

2. **驗證資料庫**：
   ```sql
   SELECT current_mode_id, last_updated_by
   FROM site_config
   WHERE site_id = 'other';
   -- 應該看到 current_mode_id = 15 (模式一)
   ```

3. **B 人員下午工作**：
   - 開啟軟體
   - **預期結果**：應自動顯示「模式一」
   - 不需要手動切換或設定

4. **B 人員切換到鑄造廠**：
   - 點擊場域切換按鈕
   - **預期結果**：自動顯示鑄造廠的當前模式
   - 如果 A 人員下午也調整了鑄造廠的模式，B 會看到最新的

## 常見問題

### Q: 如果資料庫中沒有該場域的記錄會怎樣？
A: 系統會記錄日誌 `No site config found for: {siteId}`，但不會報錯，軟體會正常運作，只是不會套用任何模式。

### Q: 如果 current_mode_id 是 NULL 會怎樣？
A: 系統會記錄 `No mode set for site: {siteId}`，不會套用模式，保持原有狀態。

### Q: 載入配置會覆蓋本地的設定嗎？
A: 是的。每次啟動和切換場域時，都會從資料庫載入最新配置並套用，確保所有實例都使用相同的設定。

### Q: 這會影響同步功能嗎？
A: 不會。載入配置後，同步服務會繼續監控資料庫的變更，當其他實例修改模式時，仍然會即時同步。

### Q: 為什麼要在切換場域時重新載入？
A: 因為不同場域可能有不同的設定。例如：
- 其他廠域可能設為「模式一」
- 鑄造廠可能設為「模式二」
- 切換時重新載入確保顯示正確的場域配置

## 效益

1. **一致性**：所有使用者看到的都是相同的配置
2. **即時性**：啟動時立即載入最新設定
3. **便利性**：不需要手動同步或確認設定
4. **可靠性**：資料庫是唯一的真實來源(Single Source of Truth)
5. **追溯性**：從日誌可以清楚看到配置載入的歷史

## 與同步功能的關係

這個功能與原有的同步機制是互補的：

| 功能 | 觸發時機 | 用途 |
|------|----------|------|
| **自動載入配置** | 啟動、切換場域 | 確保初始狀態正確 |
| **即時同步** | 其他實例變更時 | 保持運行中的實例同步 |

兩者結合確保：
- 啟動時就是最新狀態 (自動載入)
- 運行中保持同步 (即時同步)
- 切換場域時更新狀態 (自動載入)
