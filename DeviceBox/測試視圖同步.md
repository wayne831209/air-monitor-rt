# 視圖同步測試指南

## 新的同步機制

**重要變更**：不再使用啟動時的場域選擇下拉選單。同步完全根據目前顯示的視圖自動進行：

- **其他廠域視圖** (`其它廠域_空壓系統即時狀態`) → 同步場域 ID: `other`
- **鑄造廠視圖** (`鑄造廠域_空壓系統即時狀態`) → 同步場域 ID: `foundry`

## 運作原理

1. **啟動時**：程式啟動在預設視圖模式（其他廠域），自動開始同步 `other` 場域
2. **切換視圖時**：點擊左上角場域切換按鈕時，程式會：
   - 停止舊場域的同步服務
   - 啟動新場域的同步服務
   - 開始監聽新場域的配置變更
3. **同步規則**：
   - 所有顯示「其他廠域」的實例 → 互相同步
   - 所有顯示「鑄造廠」的實例 → 互相同步
   - 不同視圖的實例 → **不會互相影響**

## 測試步驟

### 測試 1：其他廠域同步

1. **開啟實例 A**
   - 啟動 DeviceBox.exe
   - 確認顯示「其它廠域_空壓系統即時狀態」
   - 記下目前模式

2. **開啟實例 B**
   - 啟動第二個 DeviceBox.exe
   - 確認顯示「其它廠域_空壓系統即時狀態」

3. **測試同步**
   - 在實例 A 中點擊 label3（模式名稱）切換模式
   - **預期結果**：實例 B 應在 5 秒內自動更新為相同模式

### 測試 2：鑄造廠同步

1. **實例 A**：點擊左上角場域切換按鈕
   - 介面應切換到「鑄造廠域_空壓系統即時狀態」
   - 顯示三台空壓機

2. **實例 B**：點擊左上角場域切換按鈕
   - 介面應切換到「鑄造廠域_空壓系統即時狀態」

3. **測試同步**
   - 在實例 A 中點擊 label3 切換模式
   - **預期結果**：實例 B 應在 5 秒內自動更新為相同模式

### 測試 3：不同視圖不互相干擾

1. **實例 A**：切換到「其它廠域」
2. **實例 B**：切換到「鑄造廠域」（保持不同視圖）
3. **測試隔離**：
   - 在實例 A（其他廠域）切換模式
   - **預期結果**：實例 B（鑄造廠）**不應該**改變模式
   - 在實例 B（鑄造廠）切換模式
   - **預期結果**：實例 A（其他廠域）**不應該**改變模式

### 測試 4：動態視圖切換同步

1. **開啟實例 A 和 B**，都在「其它廠域」
2. **實例 A**：切換模式到「模式一」
3. **實例 B**：應自動同步為「模式一」
4. **實例 B**：點擊場域切換，切到「鑄造廠域」
5. **實例 A**：改變模式到「模式二」
6. **預期結果**：實例 B（現在在鑄造廠視圖）**不應該**改變（保持模式一）
7. **實例 B**：點擊場域切換，切回「其它廠域」
8. **預期結果**：實例 B 應該在 5 秒內自動同步為「模式二」（因為回到相同視圖）

## 日誌檢查

檢查 `DeviceBox\bin\Debug\debug_*.log` 檔案中的關鍵訊息：

```
[MainForm] View-based sync initialized for: other (OtherFactories)
```
→ 啟動時初始化同步

```
[MainForm] Switching sync site to: foundry (CastingFactory)
[MainForm] Sync site switched successfully to: foundry
```
→ 視圖切換成功

```
[MainForm] *** SYNC EVENT RECEIVED *** Event SiteId: other, Current View Site: other (OtherFactories)
[MainForm] *** APPLYING SYNC *** Site: other, Version: 15
```
→ 同場域同步觸發

```
[MainForm] *** SYNC EVENT RECEIVED *** Event SiteId: other, Current View Site: foundry (CastingFactory)
[MainForm] *** IGNORING *** Config update from different site. Current view: foundry (CastingFactory), Event: other
```
→ 不同場域更新被正確忽略

## 資料庫驗證

執行以下 SQL 確認每個場域獨立追蹤：

```sql
-- 查看兩個場域的配置
SELECT 
	site_id,
	site_name,
	current_mode_id,
	config_version,
	last_updated,
	updated_by
FROM site_config
ORDER BY site_id;
```

**預期結果**：
- `other` 和 `foundry` 應該有各自的 `current_mode_id` 和 `config_version`
- 當你在不同視圖切換模式時，只有對應的場域記錄應該更新

## 常見問題

### Q: 切換視圖時會發生什麼？
A: 舊的同步服務會停止，新的同步服務會啟動，並立即檢查新場域的配置狀態。

### Q: 如果我在其他廠域視圖下，鑄造廠的配置改變了會影響我嗎？
A: 不會。你只會接收到跟你當前視圖相同場域的同步事件。

### Q: 啟動時會顯示場域選擇對話框嗎？
A: 不會。程式會直接啟動到預設視圖（其他廠域），並自動開始同步。

### Q: 兩個實例在同一電腦上會互相干擾嗎？
A: 不會，只要它們顯示相同的視圖，它們會同步；如果顯示不同視圖，它們彼此獨立。

## 技術細節

### 場域 ID 映射
- `ViewMode.OtherFactories` → 場域 ID: `"other"`
- `ViewMode.CastingFactory` → 場域 ID: `"foundry"`

### 相關方法
- `GetCurrentSiteId()`: 根據 `currentViewMode` 返回場域 ID
- `InitializeViewBasedSync()`: 啟動時初始化同步
- `SwitchSyncSite()`: 視圖切換時重新綁定同步服務
- `Factory_Click()`: 視圖切換事件，會自動調用 `SwitchSyncSite()`
