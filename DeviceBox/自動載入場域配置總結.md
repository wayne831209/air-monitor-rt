# 自動載入場域配置 - 功能總結

## ✅ 已實作功能

### 1. 啟動時自動載入配置
- ✅ 軟體啟動時自動從資料庫 `site_config` 讀取當前視圖場域的最新配置
- ✅ 自動套用資料庫中設定的模式 (`current_mode_id`)
- ✅ 更新 UI 顯示 (label3, label4)
- ✅ 套用模式的排程到設備配置
- ✅ 刷新廠域顯示

### 2. 切換場域時自動載入配置
- ✅ 點擊左上角場域切換按鈕時自動載入目標場域的最新配置
- ✅ 停止舊場域的同步服務
- ✅ 載入新場域的配置並套用
- ✅ 啟動新場域的同步服務

### 3. 完整的日誌追蹤
- ✅ 記錄配置載入過程
- ✅ 記錄資料庫查詢
- ✅ 記錄模式套用狀態
- ✅ 記錄錯誤和異常

## 🎯 解決的問題

### 問題 1：多人協作不同步
**情境**：
- A 人員上午開啟軟體，設定「其他廠域」為「模式一」
- B 人員下午開啟軟體，但看到的是舊的設定

**解決方案**：
- B 人員啟動軟體時，系統自動從資料庫讀取最新的 `current_mode_id`
- 自動套用 A 人員設定的「模式一」
- 確保 B 看到的是最新狀態

### 問題 2：切換場域後配置不正確
**情境**：
- 軟體在「其他廠域」顯示「模式一」
- 切換到「鑄造廠域」後，應該顯示該場域的配置，而不是沿用「模式一」

**解決方案**：
- 切換場域時自動讀取目標場域的 `site_config`
- 套用該場域的 `current_mode_id`
- 確保每個場域顯示其專屬的配置

## 📋 實作細節

### 新增的方法

#### `LoadAndApplySiteConfig(string siteId)`
**位置**：`MainForm.cs`

**功能**：
1. 從資料庫讀取指定場域的配置
2. 檢查是否有設定的模式 ID
3. 根據模式 ID 載入完整的模式資料
4. 套用模式到 UI 和設備配置

**呼叫時機**：
- 軟體啟動時 (`InitializeViewBasedSync`)
- 切換場域時 (`SwitchSyncSite`)

**程式碼流程**：
```csharp
LoadAndApplySiteConfig(siteId)
  ↓
database.LoadSiteConfig(siteId)  // 從資料庫讀取
  ↓
ModeSelectForm.GetModeById(...)  // 載入模式資料
  ↓
更新 currentMode, label3, label4, isManualMode
  ↓
ModeSelectForm.ApplyModeSchedulesToConfig(mode)  // 套用排程
  ↓
config.LoadConfig()  // 重新載入配置
  ↓
RefreshFactoryDisplay()  // 刷新顯示
```

### 修改的方法

#### `InitializeViewBasedSync()`
**變更**：新增 `LoadAndApplySiteConfig(currentSiteId)` 呼叫

**原始流程**：
```
InitializeViewBasedSync()
  ↓
建立同步服務
  ↓
啟動同步
```

**新流程**：
```
InitializeViewBasedSync()
  ↓
LoadAndApplySiteConfig(currentSiteId)  // ← 新增
  ↓
建立同步服務
  ↓
啟動同步
```

#### `SwitchSyncSite()`
**變更**：在啟動新同步服務之前載入配置

**原始流程**：
```
SwitchSyncSite()
  ↓
停止舊同步服務
  ↓
啟動新同步服務
```

**新流程**：
```
SwitchSyncSite()
  ↓
停止舊同步服務
  ↓
LoadAndApplySiteConfig(newSiteId)  // ← 新增
  ↓
啟動新同步服務
```

## ⚙️ 設定與維護

### 資料庫需求

**必要資料表**：`site_config`

**必要欄位**：
- `site_id` (VARCHAR) - 場域 ID
- `site_name` (VARCHAR) - 場域名稱
- `current_mode_id` (INT, nullable) - 當前模式 ID
- `config_version` (INT) - 配置版本
- `last_updated_by` (VARCHAR) - 最後更新者
- `updated_at` (TIMESTAMP) - 更新時間

**資料範例**：
```sql
INSERT INTO site_config (site_id, site_name, current_mode_id, config_version)
VALUES 
('other', '其他場域', 15, 1),
('foundry', '鑄造廠', 20, 1);
```

### 模式 ID 對應

需要確保 `current_mode_id` 對應的模式存在於系統中。

**常見模式 ID**：
- 1 - 手動模式
- 15 - 模式一
- 20 - 模式二
- 25 - 模式三
- (根據您的實際系統調整)

## 🔄 與同步功能的關係

| 時機 | 自動載入配置 | 即時同步 |

**互補關係**：
- **自動載入**：確保啟動和切換時狀態正確

## 📞 疑難排解

### 問題：軟體啟動時沒有載入配置

**檢查清單**：
1. 資料庫連線是否正常
2. `site_config` 資料表是否存在
3. 場域 ID (`other`, `foundry`) 是否有記錄
4. 日誌中是否有錯誤訊息

**日誌位置**：`DeviceBox\bin\Debug\debug_*.log`

### 問題：載入的模式沒有顯示

**可能原因**：
1. `current_mode_id` 為 NULL
2. 模式 ID 不存在於系統中
3. 模式資料載入失敗

**解決方式**：
1. 檢查資料庫：`SELECT current_mode_id FROM site_config WHERE site_id = 'other'`
2. 檢查日誌：搜尋 "Mode not found with ID"
3. 確認模式 ID 對應關係

### 問題：切換場域後配置沒有更新

**檢查清單**：
1. 日誌中是否有 "Switching sync site to:"
2. 日誌中是否有 "Loading site config from database"
3. 目標場域是否有配置記錄
4. 是否有錯誤訊息
