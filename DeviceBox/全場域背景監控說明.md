# 全場域背景監控推播功能說明

## 功能概述

已將推播功能改為**全場域背景監控**，不再受限於當前顯示的視圖。無論畫面顯示「其他廠域」或「鑄造廠域」，系統都會持續監控所有工廠的所有設備狀態，一旦發現異常立即推播。

## 主要變更

### 修改前 ❌
- 只監控當前視圖顯示的工廠
- 切換到「其他廠域」→ 只監控其他廠域的設備
- 切換到「鑄造廠域」→ 只監控鑄造廠的設備
- **問題**：未顯示的工廠異常不會被通知

### 修改後 ✅
- **全場域背景監控**
- 無論當前顯示哪個視圖，都持續監控所有工廠
- 任何工廠的任何設備異常都會立即推播
- **優點**：不會遺漏任何異常

## 技術實作

### 1. UpdateTimer_Tick 新增背景監控

**修改位置**：`MainForm.cs` - `UpdateTimer_Tick()`

```csharp
private void UpdateTimer_Tick(object sender, EventArgs e)
{
	try
	{
		UpdateAllFactories();           // 更新當前視圖的UI
		ExecuteScheduleControl();       // 執行排程控制
		MonitorAllDevicesInBackground(); // ← 新增：背景監控所有設備
	}
	catch (Exception ex)
	{
		System.Diagnostics.Debug.WriteLine("Update failed: " + ex.Message);
	}
}
```

### 2. 新增背景監控方法

#### MonitorAllDevicesInBackground()
**功能**：遍歷所有工廠，檢查所有設備狀態

**監控項目**：
1. **空壓超限**
2. **溫度超限**
3. **設備警報**
4. **設備故障**

**處理流程**：
```
遍歷所有工廠
  ↓
檢查 Modbus 連線狀態
  ↓
讀取空壓和溫度值
  ↓
檢查是否超限 → 發送推播
  ↓
遍歷該工廠的所有空壓機
  ↓
檢查警報/故障 DI → 發送推播
```

#### CheckPressureLimitInBackground()
**功能**：背景檢查空壓是否超限（不更新 UI）

**參數**：
- `valueText` - 空壓數值
- `limits` - 上下限設定
- `deviceName` - 設備名稱

**邏輯**：
```csharp
if (value > upperLimit || value < lowerLimit)
{
	OnPressureOverLimit(deviceName, valueText, limits);
}
```

#### CheckTempLimitInBackground()
**功能**：背景檢查溫度是否超限（不更新 UI）

**參數**：
- `valueText` - 溫度數值
- `limits` - 上下限設定
- `deviceName` - 設備名稱

**邏輯**：
```csharp
if (value > upperLimit || value < lowerLimit)
{
	OnTempOverLimit(deviceName, valueText, limits);
}
```

### 3. 與原有監控的關係

| 功能 | 負責內容 | 更新對象 |
|------|---------|---------|
| **UpdateAllFactories()** | 更新當前視圖的 UI 顯示 | UI Labels |
| **MonitorAllDevicesInBackground()** | 背景監控所有設備狀態 | 推播通知 |

**設計理念**：
- UI 更新只關注當前顯示的工廠（效能考量）
- 推播監控涵蓋所有工廠（安全考量）

## 監控範圍

### 完整監控項目

| 監控類型 | 檢查內容 | 通知條件 |
|---------|---------|---------|
| **空壓超限** | 所有工廠的空壓值 | 超過上限或低於下限 |
| **溫度超限** | 所有工廠的溫度值 | 超過上限或低於下限 |
| **設備警報** | 所有空壓機的警報 DI | 警報 DI 觸發 |
| **設備故障** | 所有空壓機的故障 DI | 故障 DI 觸發 |

### 監控頻率

**更新週期**：根據 `UpdateTimer` 設定
- 典型值：1-5 秒
- 每次 Timer Tick 都會執行背景監控

## 使用情境

### 情境 1：顯示其他廠域時，鑄造廠設備故障

**過程**：
1. 使用者正在查看「其他廠域」視圖
2. 鑄造廠的 CO-32 發生故障
3. 背景監控偵測到故障
4. **立即發送 Teams 通知**

**通知內容**：
```
🚨 設備故障

設備名稱: CO-32
狀態: 故障
時間: 2026-07-03 15:30:00
```

**Debug 日誌**：
```
[背景監控] 遍歷工廠: 鑄造一廠
[推播] 設備狀態變更! 設備=CO-32, 上次狀態=正常, 當前狀態=故障
[Teams通知] 設備故障通知已發送給 user@example.com
```

### 情境 2：顯示鑄造廠時，其他廠域空壓超限

**過程**：
1. 使用者正在查看「鑄造廠域」視圖
2. 其他廠域的某工廠空壓超限
3. 背景監控偵測到超限
4. **立即發送 Teams 通知**

**通知內容**：
```
⚠️ 空壓超限警報

設備: CO-32, CO-38
當前數值: 8.5
上限: 8.0
下限: 6.0
時間: 2026-07-03 15:30:00
```

### 情境 3：所有場域同時監控

**過程**：
1. 使用者正在查看任一視圖
2. 多個工廠同時發生異常：
   - 鑄造廠 CO-32 溫度超限
   - 其他廠域 CO-38 警報
   - 其他廠域 CO-39 空壓超限
3. 背景監控依序偵測所有異常
4. **依序發送 Teams 通知**（受冷卻時間限制）

## 效能考量

### 1. 背景監控開銷

**增加的處理**：
- 遍歷所有工廠
- 讀取所有 Modbus 數據
- 檢查所有上下限

**優化設計**：
- 只在 ConnectState = true 時檢查
- 跳過 address_val = null 的設備
- 使用已快取的 Modbus 數據

### 2. 通知頻率控制

**防止通知風暴**：
1. **冷卻時間**：5 分鐘
2. **狀態追蹤**：避免重複通知相同狀態
3. **條件判斷**：只在狀態變更時通知

### 3. UI 更新分離

**設計優點**：
- UI 更新只處理當前視圖（保持流暢）
- 背景監控獨立運行（不影響 UI）
- 兩者互不干擾

## 注意事項

### 1. 網路需求
- 所有工廠的 Modbus 連線必須正常
- 斷線的工廠會被自動跳過

### 2. 通知頻率
- 冷卻時間仍然生效（5 分鐘）
- 多個異常可能無法同時通知

### 3. 效能影響
- 背景監控會增加些微 CPU 使用
- 已優化，正常情況影響極小

### 4. 測試建議
- 部署前充分測試各種情境
- 確認所有工廠都能正常監控
