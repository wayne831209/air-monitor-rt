# 推播設定資料庫化功能說明

## 功能概述

將所有推播相關的設定改為從資料庫讀取，使用者可以透過修改資料庫來動態調整推播行為，不需要修改程式碼或重新編譯。

## 新增設定項目

### 1. 推播開關 (teams_enabled)
- **設定鍵值**: `teams_enabled`
- **設定值**: `true` 或 `false`
- **說明**: 控制是否啟用 Teams 推播功能
- **預設值**: `false`

### 2. 推播人員清單 (teams_email)
- **設定鍵值**: `teams_email`
- **設定值**: Email 地址字串（支援逗號或分號分隔多組）
- **說明**: 推播通知的收件人列表
- **格式範例**: `user1@example.com,user2@example.com;user3@example.com`
- **預設值**: 空字串

### 3. 推播間隔時間 (notification_cooldown_minutes) ⭐ 新增
- **設定鍵值**: `notification_cooldown_minutes`
- **設定值**: 數字（分鐘）
- **說明**: 兩次推播之間的最小間隔時間，避免短時間內重複推播
- **預設值**: `5` (5 分鐘)
- **設定範圍**: 建議 1-60 分鐘

### 4. 超限延遲推播時間 (alarm_delay_minutes) ⭐ 新增
- **設定鍵值**: `alarm_delay_minutes`
- **設定值**: 數字（分鐘）
- **說明**: 設備超過上下限後，需持續超限多久才發送推播（避免瞬間異常誤報）
- **預設值**: `0` (立即推播)
- **設定範圍**: 0-60 分鐘
- **特殊說明**: 設定為 0 表示立即推播，設定為 5 表示超限持續 5 分鐘後才推播

## 資料庫操作

### 初始化新設定
執行 SQL 腳本來新增推播設定項目：
```bash
DeviceBox\Database\2_新增推播設定.sql
```

此腳本會自動插入以下設定：
- `notification_cooldown_minutes` = 5（預設 5 分鐘）
- `alarm_delay_minutes` = 0（預設立即推播）

### 查詢目前設定
```sql
USE ycm_energy;

SELECT 
	setting_key AS '設定鍵值',
	setting_value AS '設定值',
	description AS '說明',
	updated_at AS '更新時間'
FROM notification_settings
ORDER BY setting_key;
```

### 修改推播開關
```sql
-- 啟用推播
UPDATE notification_settings 
SET setting_value = 'true' 
WHERE setting_key = 'teams_enabled';

-- 停用推播
UPDATE notification_settings 
SET setting_value = 'false' 
WHERE setting_key = 'teams_enabled';
```

### 修改推播人員
```sql
-- 新增或修改推播人員（逗號分隔）
UPDATE notification_settings 
SET setting_value = 'user1@example.com,user2@example.com,user3@example.com' 
WHERE setting_key = 'teams_email';

-- 清空推播人員（使用 Webhook URL 預設收件者）
UPDATE notification_settings 
SET setting_value = '' 
WHERE setting_key = 'teams_email';
```

### 修改推播間隔時間
```sql
-- 設定為 3 分鐘
UPDATE notification_settings 
SET setting_value = '3' 
WHERE setting_key = 'notification_cooldown_minutes';

-- 設定為 10 分鐘
UPDATE notification_settings 
SET setting_value = '10' 
WHERE setting_key = 'notification_cooldown_minutes';
```

### 修改超限延遲推播時間
```sql
-- 立即推播（預設）
UPDATE notification_settings 
SET setting_value = '0' 
WHERE setting_key = 'alarm_delay_minutes';

-- 超限持續 2 分鐘後才推播
UPDATE notification_settings 
SET setting_value = '2' 
WHERE setting_key = 'alarm_delay_minutes';

-- 超限持續 5 分鐘後才推播
UPDATE notification_settings 
SET setting_value = '5' 
WHERE setting_key = 'alarm_delay_minutes';
```

## 技術實作

### Config.cs
新增屬性：
```csharp
public int NotificationCooldownMinutes { get; set; } = 5; // 推播間隔時間
public int AlarmDelayMinutes { get; set; } = 0; // 超限延遲推播時間
```

啟動時從資料庫載入：
```csharp
private void LoadTeamsNotificationSettingsFromDatabase()
{
	var settings = _deviceDatabase.LoadNotificationSettings();

	// 載入推播間隔
	if (settings.ContainsKey("notification_cooldown_minutes"))
	{
		NotificationCooldownMinutes = int.Parse(settings["notification_cooldown_minutes"]);
	}

	// 載入超限延遲
	if (settings.ContainsKey("alarm_delay_minutes"))
	{
		AlarmDelayMinutes = int.Parse(settings["alarm_delay_minutes"]);
	}
}
```

### TeamsNotificationService.cs
建構子接收動態冷卻時間：
```csharp
public TeamsNotificationService(string webhookUrl, string notificationEmail = "", int cooldownMinutes = 5)
{
	_notificationCooldown = TimeSpan.FromMinutes(cooldownMinutes);
	// ...
}
```

### MainForm.cs
#### 初始化 Teams 服務
```csharp
private void InitializeTeamsNotification()
{
	teamsNotificationService = new TeamsNotificationService(
		config.TeamsWebhookUrl, 
		config.TeamsNotificationEmail,
		config.NotificationCooldownMinutes); // 傳入動態冷卻時間
}
```

#### 超限延遲推播邏輯
```csharp
// 追蹤異常開始時間
private Dictionary<string, DateTime> abnormalStartTimes = new Dictionary<string, DateTime>();

private void SendCombinedAbnormalNotification(...)
{
	// 為每種異常類型建立追蹤 key
	string key = "temp:" + string.Join(",", tempAbnormal.OrderBy(x => x));

	// 首次偵測到異常時記錄開始時間
	if (!abnormalStartTimes.ContainsKey(key))
	{
		abnormalStartTimes[key] = DateTime.Now;
	}

	// 檢查是否已持續超過設定時間
	TimeSpan duration = DateTime.Now - abnormalStartTimes[key];
	if (duration.TotalMinutes >= config.AlarmDelayMinutes)
	{
		// 符合推播條件，發送通知
		abnormalMessages.Add($"溫度異常: {string.Join(", ", tempAbnormal)}");
	}
}
```

## 使用情境

### 情境 1：立即推播（預設）
```sql
UPDATE notification_settings SET setting_value = '0' WHERE setting_key = 'alarm_delay_minutes';
UPDATE notification_settings SET setting_value = '5' WHERE setting_key = 'notification_cooldown_minutes';
```
- 設備超限後立即推播
- 5 分鐘內不會重複推播相同異常

### 情境 2：避免瞬間異常誤報
```sql
UPDATE notification_settings SET setting_value = '2' WHERE setting_key = 'alarm_delay_minutes';
UPDATE notification_settings SET setting_value = '5' WHERE setting_key = 'notification_cooldown_minutes';
```
- 設備超限後需持續 2 分鐘才推播
- 5 分鐘內不會重複推播相同異常
- 適合有瞬間波動的環境

### 情境 3：減少推播頻率
```sql
UPDATE notification_settings SET setting_value = '5' WHERE setting_key = 'alarm_delay_minutes';
UPDATE notification_settings SET setting_value = '15' WHERE setting_key = 'notification_cooldown_minutes';
```
- 設備超限後需持續 5 分鐘才推播
- 15 分鐘內不會重複推播相同異常
- 適合不緊急的監控情境

## 重要提醒

### 設定生效時機
⚠️ **所有設定只在軟體啟動時載入一次**，修改資料庫後需要：
1. 關閉 DeviceBox 軟體
2. 重新啟動 DeviceBox 軟體

### 超限延遲推播的行為
- **重啟軟體會重置追蹤**: 如果設備已超限 3 分鐘，此時重啟軟體，計時會從 0 開始
- **異常恢復會清除追蹤**: 如果設備超限 1 分鐘後恢復正常，再次超限時計時會重新開始
- **設備組合變更會重置**: 例如原本是 CO-32 超限，後來變成 CO-32、CO-35 都超限，計時會重新開始

### 推播間隔的行為
- 推播間隔是**全局的**，不分異常類型
- 如果在 5 分鐘內先推播了溫度異常，空壓異常也會被冷卻時間阻擋
- 這是為了避免短時間內推播太多訊息

## Debug 訊息

啟動時會輸出：
```

[Config] Alarm Delay: 0 minutes
[Teams通知] 推播間隔時間: 5 分鐘
```

```

[推播延遲] 溫度異常已持續 0.5 分鐘，尚未達到推播條件 (2 分鐘)
[推播延遲] 溫度異常已持續 2.1 分鐘，符合推播條件
[推播] 偵測到符合推播條件的異常:
  溫度異常: CO-32, CO-35
```
