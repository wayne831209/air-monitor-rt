# 全局計時器推播機制說明

## 概述

推播延遲機制改用**全局計時器**，不再針對每個異常類型或設備分別計時。

## 核心邏輯

### ✅ 新版邏輯（全局計時器）

```
只要有任何設備異常（空壓/溫度超限） → 啟動計時器
所有設備恢復正常 → 計時器歸零
計時器達到設定時間 → 推播所有當前異常
```

### ❌ 舊版邏輯（已廢棄）

```
每個異常類型分別計時（空壓、溫度各自計時）
每個異常類型達到時間才分別推播
```

## 實際運作範例

### 範例 1：單一設備異常

```
時間  | 設備狀態              | 計時器狀態        | 推播
------|---------------------|-----------------|------
0:00  | 所有正常             | (未啟動)         | -
0:10  | CO-32 空壓超限       | 啟動 (0秒)       | -
0:30  | CO-32 空壓超限       | 運行中 (20秒)    | -
1:00  | CO-32 空壓超限       | 運行中 (50秒)    | -
1:10  | CO-32 空壓超限       | 達到 60秒 ✓     | 推播「空壓異常: CO-32」
1:30  | CO-32 恢復正常       | 歸零            | -
```

### 範例 2：多設備交錯異常（關鍵範例）

```
時間  | 設備狀態                     | 計時器狀態        | 推播
------|----------------------------|-----------------|------
0:00  | 所有正常                    | (未啟動)         | -
0:10  | CO-32 空壓超限              | 啟動 (0秒)       | -
0:20  | CO-32 空壓超限              | 運行中 (10秒)    | -
	  | CO-38 溫度超限              |                 |
0:30  | CO-32 恢復正常 ✓            | 繼續運行 (20秒)   | - (因為 CO-38 還異常)
	  | CO-38 溫度超限              |                 |
1:00  | CO-38 溫度超限              | 運行中 (50秒)    | -
1:10  | CO-38 溫度超限              | 達到 60秒 ✓     | 推播「溫度異常: CO-38」
1:30  | CO-38 恢復正常              | 歸零            | -
```

**重點：**
- CO-32 在 0:10 開始計時
- CO-38 在 0:20 異常，計時器**繼續運行**（不重新計時）
- CO-32 在 0:30 恢復正常，但 CO-38 還異常，所以計時器**繼續運行**
- 計時器在 1:10 達到 60 秒，推播「溫度異常: CO-38」
- 如果 CO-32 還在異常，會推播「空壓異常: CO-32, 溫度異常: CO-38」

### 範例 3：全部恢復後重新計時

```
時間  | 設備狀態              | 計時器狀態        | 推播
------|---------------------|-----------------|------
0:00  | CO-32 空壓超限       | 啟動 (0秒)       | -
0:30  | CO-32 空壓超限       | 運行中 (30秒)    | -
0:40  | CO-32 恢復正常       | 歸零 ✓          | -
1:00  | CO-35 空壓超限       | 重新啟動 (0秒)   | - (重新計時)
2:00  | CO-35 空壓超限       | 達到 60秒 ✓     | 推播「空壓異常: CO-35」
```

**重點：**
- CO-32 異常但在 0:40 恢復正常，計時器歸零
- CO-35 在 1:00 異常，計時器**重新開始計時**（從 0 秒開始）

### 範例 4：警報/故障立即推播

```
時間  | 設備狀態              | 計時器狀態        | 推播
------|---------------------|-----------------|------
0:00  | 所有正常             | (未啟動)         | -
0:10  | CO-32 空壓超限       | 啟動 (0秒)       | -
0:20  | CO-32 警報          | 不受計時器影響    | 立即推播「設備警報: CO-32」
0:30  | CO-32 空壓超限       | 運行中 (20秒)    | -
1:10  | CO-32 空壓超限       | 達到 60秒 ✓     | 推播「空壓異常: CO-32」
```

**重點：**
- 設備警報和故障**不受延遲機制影響**，立即推播
- 空壓/溫度異常受延遲機制控制

## 設定參數

### `alarm_delay_minutes`（推播延遲時間）

- **預設值：** 1 分鐘
- **用途：** 空壓/溫度超限需要持續多久才推播
- **設定位置：** AlarmLimitSettingForm 或資料庫 `notification_settings` 表

```sql
UPDATE notification_settings 
SET setting_value = '0'  -- 0 = 立即推播，不延遲
WHERE setting_key = 'alarm_delay_minutes';
```

### `notification_cooldown_minutes`（推播冷卻時間）

- **預設值：** 5 分鐘
- **用途：** 同一類型的異常推播後，多久內不再重複推播
- **設定位置：** AlarmLimitSettingForm 或資料庫 `notification_settings` 表

```sql
UPDATE notification_settings 
SET setting_value = '10'  -- 10 分鐘冷卻時間
WHERE setting_key = 'notification_cooldown_minutes';
```

## 實作細節

### 程式碼變數

```csharp
// 全局計時器：只要有任何設備異常就啟動
private DateTime? globalAbnormalStartTime = null;

// 當前異常設備集合
private HashSet<string> currentAbnormalDevices = new HashSet<string>();
```

### 計時器管理邏輯

```csharp
// 1. 檢查是否有空壓/溫度異常
bool hasPressureTempAbnormal = pressureAbnormal.Count > 0 || tempAbnormal.Count > 0;

// 2. 管理全局計時器
if (hasPressureTempAbnormal)
{
	// 有異常：啟動或繼續計時
	if (!globalAbnormalStartTime.HasValue)
		globalAbnormalStartTime = DateTime.Now;
}
else
{
	// 沒有異常：重置計時器
	globalAbnormalStartTime = null;
}

// 3. 檢查是否達到推播條件
TimeSpan duration = DateTime.Now - globalAbnormalStartTime.Value;
if (duration.TotalMinutes >= config.AlarmDelayMinutes)
{
	// 推播所有當前異常
}
```

啟動計時器：
```
[推播延遲] 全局計時器啟動，異常設備: CO-32, CO-38
```

計時器運行中：
```
[推播延遲] 全局計時器運行中，已持續 0.5 分鐘，異常設備: CO-32, CO-38
[推播延遲] 異常已持續 0.5 分鐘，尚未達到推播條件 (1 分鐘)
```

達到推播條件：
```
[推播延遲] 空壓異常已持續 1.0 分鐘，符合推播條件
[推播] 偵測到符合推播條件的異常:
  空壓異常: CO-32, CO-38
```

計時器歸零：
```
[推播延遲] 所有設備恢復正常，計時器歸零
```

## 與舊版的差異

| 項目           | 舊版（已廢棄）                | 新版（全局計時器）            |
|----------------|------------------------------|----------------------------|
| 計時方式       | 每個異常類型分別計時           | 全局統一計時                |
| 計時器數量     | 多個（空壓、溫度各自計時）     | 1 個（全局計時器）          |
| 異常恢復       | 該類型計時器歸零              | 所有設備正常後才歸零         |
| 推播時機       | 每個類型達到時間分別推播       | 達到時間一次推播所有異常     |
| 實作複雜度     | 高（需要追蹤多個計時器）       | 低（只有一個計時器）         |

## 測試建議

### 測試 1：單一設備超限
1. 設定延遲時間為 1 分鐘
2. 讓 CO-32 空壓超限
3. 觀察 Debug 輸出，應該看到計時器啟動
4. 等待 1 分鐘，應該收到推播

### 測試 2：多設備交錯
1. 設定延遲時間為 1 分鐘
2. 時間 0:00 - 讓 CO-32 空壓超限
3. 時間 0:30 - 讓 CO-32 恢復正常，但 CO-38 溫度超限
4. 時間 1:00 - 應該收到推播「溫度異常: CO-38」

### 測試 3：全部恢復後重新計時
1. 設定延遲時間為 1 分鐘
2. 時間 0:00 - 讓 CO-32 空壓超限
3. 時間 0:30 - 讓 CO-32 恢復正常（計時器應該歸零）
4. 時間 1:00 - 讓 CO-35 空壓超限（計時器應該重新啟動）
5. 時間 2:00 - 應該收到推播「空壓異常: CO-35」

### 測試 4：立即推播
1. 觸發設備警報或故障
2. 應該立即收到推播，不受延遲機制影響
