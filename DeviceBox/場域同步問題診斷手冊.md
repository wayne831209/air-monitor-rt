# 場域同步問題診斷手冊

## 🔍 問題現象
- A 軟體：其他場域，模式一
- B 軟體：鑄造廠，切換到手動模式
- **錯誤結果**：A 軟體跟著改變（不應該！）

## 📋 診斷步驟

### 第一步：開啟 Output 視窗
1. Visual Studio → 檢視 → 輸出 (Ctrl+Alt+O)
2. 或直接在執行程式時觀察 Debug 輸出

### 第二步：執行測試並收集日誌

#### 測試場景：
1. **啟動 A 軟體**
   ```
   雙擊 DeviceBox.exe
   選擇：其他場域
   切換到：模式一
   ```

2. **啟動 B 軟體**
   ```
   再次雙擊 DeviceBox.exe（不要關閉 A）
   選擇：鑄造廠
   ```

3. **B 軟體切換模式**
   ```
   在 B 軟體中切換到：手動模式
   ```

4. **觀察 A 軟體**
   - 是否跟著改變？（不應該）
   - 觀察 Output 視窗的日誌

### 第三步：分析日誌輸出

#### 正常情況應該看到：

**A 軟體啟動（其他場域）：**
```
[SiteManager] Instance created for PID 12345, config file: C:\...\site_12345.config
[SiteManager] Loaded site: other - 其他場域
[MainForm] Starting sync service for site: other (其他場域)
[ConfigSyncService] Initialized for site: other, version: 5
[MainForm] Config sync service started for site: other
```

**B 軟體啟動（鑄造廠）：**
```
[SiteManager] Instance created for PID 67890, config file: C:\...\site_67890.config
[SiteManager] Loaded site: foundry - 鑄造廠
[MainForm] Starting sync service for site: foundry (鑄造廠)
[ConfigSyncService] Initialized for site: foundry, version: 3
[MainForm] Config sync service started for site: foundry
```

**B 軟體切換到手動模式：**
```
[MainForm] *** SAVING MODE *** Site: foundry (鑄造廠), Mode: 手動 (ID:0)
[DeviceDatabase] UpdateSiteMode: site=foundry, mode=0, affected=1
[MainForm] Mode saved successfully to site 'foundry'
```

**5 秒後，A 軟體的同步檢查（每 5 秒一次）：**
```
[ConfigSyncService] Checking site 'other': current_version=5, last_known=5, mode=1
（沒有版本變化，不觸發事件）
```

**關鍵：A 軟體不應該看到 foundry 的更新！**

#### 異常情況（如果出現這些，就有 bug）：

**❌ 錯誤 1：A 軟體收到了 foundry 的事件**
```
[MainForm] *** SYNC EVENT RECEIVED *** Event SiteId: foundry, Current SiteId: other, Mode: 0, Version: 4
[MainForm] *** IGNORING *** Config update from different site. Current: other (其他場域), Event: foundry (鑄造廠)
```
→ 這表示 ConfigSyncService 沒有正確過濾場域

**❌ 錯誤 2：A 軟體的 CurrentSiteId 被修改了**
```
[MainForm] *** SYNC EVENT RECEIVED *** Event SiteId: foundry, Current SiteId: foundry, Mode: 0
[MainForm] *** APPLYING SYNC *** ...
```
→ 這表示 SiteManager.Instance 的 CurrentSiteId 被改變了（單例問題）

**❌ 錯誤 3：ConfigSyncService 監聽了錯誤的場域**
```
[MainForm] Starting sync service for site: other (其他場域)
[ConfigSyncService] Initialized for site: foundry, version: 3  <-- 不一致！
```
→ 這表示傳遞參數時出錯

### 第四步：資料庫驗證

在 MySQL Workbench 中執行：

```sql
-- 檢查兩個場域是否獨立
SELECT 
	site_id AS '場域',
	site_name AS '名稱',
	current_mode_id AS '模式ID',
	config_version AS '版本',
	last_updated_by AS '更新者',
	updated_at AS '時間'
FROM site_config
ORDER BY updated_at DESC;

-- 應該看到兩筆獨立的記錄：
-- foundry | 鑄造廠   | 0 | 4 | COMPUTERNAME | 2024-01-15 14:35:20
-- other   | 其他場域 | 1 | 5 | COMPUTERNAME | 2024-01-15 14:30:00
```

### 第五步：檢查配置檔案

執行目錄應該有兩個獨立的檔案：
```
C:\...\DeviceBox\
  ├── DeviceBox.exe
  ├── site_12345.config  <- A 軟體 (PID 12345)
  └── site_67890.config  <- B 軟體 (PID 67890)
```

查看 `site_12345.config` 內容：
```xml
<?xml version="1.0" encoding="utf-8"?>
<SiteConfig>
  <SiteId>other</SiteId>
  <SiteName>其他場域</SiteName>
  <UpdatedAt>2024-01-15 14:30:00</UpdatedAt>
</SiteConfig>
```

查看 `site_67890.config` 內容：
```xml
<?xml version="1.0" encoding="utf-8"?>
<SiteConfig>
  <SiteId>foundry</SiteId>
  <SiteName>鑄造廠</SiteName>
  <UpdatedAt>2024-01-15 14:35:00</UpdatedAt>
</SiteConfig>
```

## 🐛 可能的 Bug 原因

### 1. SiteManager 單例跨 Process 共享（不太可能）
- 每個 .exe Process 有獨立的記憶體空間
- 單例不會跨 Process 共享
- **機率：1%**

### 2. ConfigSyncService 沒有正確過濾 siteId
- `LoadSiteConfig(siteId)` SQL 可能寫錯
- **機率：20%**
- **檢查**：`DeviceDatabase.cs` 的 `LoadSiteConfig` 方法

### 3. 配置檔案被覆蓋
- 雖然改成 `site_{PID}.config`，但可能還有其他地方使用 `site.config`
- **機率：30%**
- **檢查**：搜尋專案中所有 `"site.config"` 字串

### 4. 事件訂閱錯誤
- 可能 A 軟體的 ConfigSyncService 被多次建立
- 或訂閱了多個場域的事件
- **機率：25%**
- **檢查**：日誌中是否有多次 "Config sync service started"

### 5. 資料庫返回錯誤資料
- `LoadSiteConfig` 沒有正確使用 WHERE 條件
- 或 siteId 參數傳遞錯誤
- **機率：24%**
- **檢查**：加上 SQL 查詢日誌

## 📝 收集完整日誌的方法

### 方法 1：使用 DebugView（推薦）
1. 下載 DebugView：https://learn.microsoft.com/en-us/sysinternals/downloads/debugview
2. 執行 DebugView（以系統管理員身分執行）
3. 勾選 Capture → Capture Global Win32
4. 執行測試
5. 儲存 log 檔案

### 方法 2：重新導向到檔案
在 `MainForm.cs` 構造函數最開始加上：
```csharp
var logPath = Path.Combine(Application.StartupPath, 
	$"debug_{Process.GetCurrentProcess().Id}.log");
var listener = new TextWriterTraceListener(logPath);
System.Diagnostics.Debug.Listeners.Add(listener);
System.Diagnostics.Debug.AutoFlush = true;
```

## 🔧 下一步行動

### 如果日誌顯示 A 軟體收到了 foundry 的更新：
→ 問題在 `ConfigSyncService` 的場域過濾
→ 檢查 `DeviceDatabase.LoadSiteConfig(siteId)` 的 SQL

### 如果日誌顯示 A 軟體的 CurrentSiteId 變成了 foundry：
→ 問題在 `SiteManager` 的狀態管理
→ 檢查是否有其他地方修改了 `CurrentSiteId`

### 如果日誌什麼都沒顯示：
→ Debug.WriteLine 可能沒有輸出
→ 使用 DebugView 或檔案日誌
