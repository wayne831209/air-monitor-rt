# 遷移失敗問題排查指南

## 🔍 問題: 程式啟動後看不到設備資料

### 快速診斷

**立即執行診斷工具:**

```
雙擊執行: 4_診斷工具.bat
```

或在命令列中:

```powershell
.\DeviceBox.exe --diagnostic
```

診斷工具會自動檢查:
1. ✅ 資料庫連線是否正常
2. ✅ 資料庫中是否有資料
3. ✅ Config 類別是否能正確載入資料

---

## 📊 診斷步驟說明

### 步驟 1: 測試資料庫連線

點擊「1. 測試資料庫連線」按鈕

**可能的結果:**

#### ✅ 成功 - 顯示類似訊息:
```
✅ 資料庫連線成功!
✅ 找到 5 個工廠:
   - [1] 裝配一廠 (192.168.210.130:502)
   - [2] 裝配二廠 (192.168.210.113:502)
   ...
✅ 總共 25 個設備
```

**動作:** 繼續步驟 2

#### ❌ 失敗 - 顯示「資料庫連線失敗」

**可能原因 A: 資料庫中沒有資料**
```
❌ 警告: 資料庫中沒有工廠資料!
```

**解決方法:**
1. 確認是否已執行過遷移工具
2. 重新執行遷移:
   ```
   雙擊執行: 2_執行資料遷移.bat
   ```
3. 在遷移工具中點擊「2. 執行資料遷移」

**可能原因 B: 資料庫連線失敗**
```
❌ 錯誤: 資料庫連線失敗!
```

**解決方法:**

1. **檢查 MySQL 是否運行:**
   ```powershell
   mysql -h 192.168.102.182 -u Client -p
   ```
   輸入密碼: `root`

2. **檢查 config.xml 中的資料庫設定:**
   ```xml
   <Database>
	   <mysql_on>1</mysql_on>
	   <IP>192.168.102.182</IP>
	   <DB>ycm_energy</DB>
	   <USER>Client</USER>
	   <Password>root</Password>
   </Database>
   ```

3. **測試網路連線:**
   ```powershell
   ping 192.168.102.182
   ```

4. **檢查防火牆:**
   - 確認 MySQL 端口 3306 沒有被防火牆阻擋

---

### 步驟 2: 測試載入配置

點擊「2. 測試載入配置」按鈕

**可能的結果:**

#### ✅ 成功 - 顯示類似訊息:
```
✅ Config.LoadConfig() 成功
載入的工廠數量: 5
✅ 成功載入工廠資料:

工廠 [1]: 裝配一廠
   Modbus: 192.168.210.130:502
   設備數量: 6
	  空壓機: 1 個
	  其他設備: 5 個
...
```

**動作:** Config 載入正常,但程式介面沒顯示資料

**可能原因:** MainForm 的初始化問題

**解決方法:**

1. 檢查 MainForm 是否正確使用 config:
   - 開啟 `MainForm.cs`
   - 搜尋 `InitializeConfig()`
   - 確認有調用 `config.LoadConfig()`

2. 查看 Visual Studio 的「輸出」視窗:
   - 偵錯 → 視窗 → 輸出
   - 查找類似訊息: `[Config] Loaded X factories from database`

#### ❌ 失敗 - 顯示「Config.Factories 是空的」

**原因:** Config 雖然成功載入 config.xml,但從資料庫讀取工廠資料失敗

**解決方法:**

1. 確認步驟 1 的資料庫測試是否成功
2. 如果步驟 1 成功但步驟 2 失敗,可能是代碼問題

**檢查 LoadFactoriesFromDatabase 方法:**

在 Visual Studio 中:
1. 按 F5 開始偵錯
2. 在 `Config.cs` 的 `LoadFactoriesFromDatabase()` 方法中設定中斷點
3. 逐步執行,查看哪一行出錯

## 🔧 常見問題與解決方案

### 問題 1: 遷移工具顯示「找不到 config.xml」

**解決:**
```powershell
# 確認 config.xml 在程式目錄
Get-ChildItem config.xml
```

如果不存在,請從備份還原或從 Git 取得。

### 問題 2: 遷移工具顯示「無法新增工廠 (可能已存在)」

**原因:** 資料庫中已有相同名稱的工廠

**解決方法 A - 清空資料庫重新遷移:**
```sql
-- 在 MySQL 中執行
DELETE FROM device_config;
DELETE FROM alarm_limits;
DELETE FROM factories;
```

**解決方法 B - 檢查現有資料:**
```sql
-- 在 MySQL 中執行
SELECT * FROM factories;
SELECT * FROM device_config;
```

如果資料正確,就不需要重新遷移。

### 問題 3: SQL 執行失敗

**錯誤訊息:** `Table 'factories' already exists`

**原因:** 表已經存在

**解決:** 不需要重複建表,直接執行步驟 2 (資料遷移)

### 問題 4: 遷移成功,但程式顯示空白介面

**檢查清單:**

1. ✅ 診斷工具步驟 1 顯示有資料
2. ✅ 診斷工具步驟 2 顯示 Config 載入成功
3. ❌ 但是 MainForm 沒有顯示設備

**可能原因:** MainForm 的顯示邏輯問題

**臨時解決方法 - 使用舊的 XML 模式:**

在 `Config.cs` 中找到 `LoadConfig()` 方法,暫時改回使用 XML:

```csharp
// 註解掉資料庫載入
// LoadFactoriesFromDatabase();

// 改用 XML 載入
LoadFactorySettings(root.Element("Factories"));
```

這樣可以先讓程式運行,然後再調查資料庫載入的問題。

## 🗂️ 手動驗證資料庫

如果診斷工具無法運行,請手動檢查:

### 在 MySQL Workbench 中執行:

```sql
USE ycm_energy;

-- 1. 檢查表是否存在
SHOW TABLES;

-- 2. 檢查工廠資料
SELECT * FROM factories;

-- 3. 檢查設備資料
SELECT COUNT(*) FROM device_config;

-- 4. 詳細查看設備
SELECT f.name, d.device_type, d.name, d.enabled
FROM device_config d
JOIN factories f ON d.factory_id = f.id;
```

**預期結果:**
- `factories` 表有 5 筆資料
- `device_config` 表有 25-30 筆資料
- `alarm_limits` 表有幾筆資料

如果這些都正常,問題在程式端的載入邏輯。

## 📞 進階診斷

如果上述都無法解決,請收集以下資訊:

1. **診斷工具的完整輸出** (複製診斷工具中的所有文字)

2. **Visual Studio 輸出視窗的內容:**
   - 偵錯 → 視窗 → 輸出
   - 複製所有 [Config] 和 [DeviceDatabase] 開頭的訊息

3. **MySQL 查詢結果:**
   ```sql
  SELECT COUNT(*) AS 工廠, 
		 (SELECT COUNT(*) FROM device_config) AS 設備,
		 (SELECT COUNT(*) FROM alarm_limits) AS 上下限
   FROM factories;
   ```

4. **config.xml 的 Database 區段:**
   ```xml
   <Database>
	   <mysql_on>?</mysql_on>
	   <IP>?</IP>
	   ...
   </Database>
   ```

提供這些資訊可以更快定位問題!
