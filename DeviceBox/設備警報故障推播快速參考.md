# 設備警報與故障推播 - 快速參考

## ✅ 新增功能

系統現在會在設備進入警報或故障狀態時，自動發送 Teams 推播通知。

## 📊 通知類型

### 1. 設備警報 ⚠️
```
⚠️ 設備警報

設備名稱: CO-32
狀態: 警報
時間: 2026-07-03 15:30:00
```
**觸發**：警報 DI 訊號觸發
**顏色**：橘色

### 2. 設備故障 🚨
```
🚨 設備故障

設備名稱: CO-32
狀態: 故障
時間: 2026-07-03 15:30:00
```
**觸發**：故障 DI 訊號觸發
**顏色**：深紅色

## 🎯 觸發規則

| 狀態變化 | 是否通知 | 通知類型 |
|---------|---------|---------|
| 正常 → 警報 | ✅ | 警報 |
| 正常 → 故障 | ✅ | 故障 |
| 運轉 → 警報 | ✅ | 警報 |
| 運轉 → 故障 | ✅ | 故障 |
| 警報 → 故障 | ✅ | 故障 |
| 警報 → 正常 | ❌ | - |
| 故障 → 正常 | ❌ | - |
| 警報 → 警報 | ❌ | (避免重複) |
| 故障 → 故障 | ❌ | (避免重複) |

## 🔧 設定需求

### 必要設定
1. **啟用 Teams 通知**
   ```xml
   <TeamsNotification>
	   <Enabled>true</Enabled>
   </TeamsNotification>
   ```

2. **設定 Webhook URL**
   ```xml
   <WebhookUrl>https://your-webhook-url</WebhookUrl>
   ```

3. **設定通知對象**（選擇性）
   ```xml
   <NotificationEmail>user@example.com</NotificationEmail>
   ```

## 🛡️ 防重複機制

### 狀態追蹤
- 記錄每個設備的上次狀態
- 只在狀態改變時發送通知

### 冷卻時間
- 5 分鐘冷卻期
- 避免短時間內重複通知

## 🔍 檢查方式

### Debug 日誌
搜尋關鍵字：
```
[推播] 設備狀態變更! 設備=CO-32
[Teams通知] 設備警報通知已發送
[Teams通知] 設備故障通知已發送
```

### Teams 頻道
直接查看 Teams 通知訊息

## 💡 使用範例

### 範例 1：警報通知
```
1. CO-32 正常運轉
2. 警報 DI 觸發
3. 系統偵測：正常 → 警報
4. 發送 Teams 通知 ⚠️
```

### 範例 2：故障通知
```
1. CO-38 處於警報狀態
2. 故障 DI 觸發
3. 系統偵測：警報 → 故障
4. 發送 Teams 通知 🚨
```

### 範例 3：恢復正常
```
1. CO-32 處於警報狀態
2. 警報解除
3. 系統偵測：警報 → 正常
4. 不發送通知（僅記錄）
```

## ⚠️ 注意事項

1. **冷卻時間**
   - 所有通知共用 5 分鐘冷卻

2. **狀態恢復**
   - 恢復正常時不通知

3. **初始狀態**
   - 啟動時所有設備初始化為正常

4. **網路需求**
   - 需要連接 Teams Webhook

## 🔧 疑難排解

### 沒有收到通知？
✓ 檢查 `TeamsNotificationEnabled = true`
✓ 檢查 Webhook URL 設定
✓ 檢查網路連線
✓ 查看 Debug 日誌錯誤訊息

### 收到重複通知？
✓ 檢查 DI 訊號是否穩定
✓ 冷卻時間已過會重新通知

### 通知延遲？
✓ 正常延遲 1-10 秒
✓ 受 UpdateTimer 週期影響

## 📋 測試方式

### 方法 1：PLC 訊號測試
1. 使用 PLC 工具設定警報/故障 DI
2. 等待程式更新週期
3. 檢查 Teams 通知

### 方法 2：程式碼測試
暫時修改程式碼：
```csharp
bool isAlarm = true;  // 強制警報
bool isFault = false;
```
