# 排程更新問題修正說明

## 🔍 問題描述

**症狀**：
編輯排程並儲存後，資料庫中的 `schedule_items` 表會一直增加，沒有刪除舊的排程項目。

**範例**：
1. 模式一有 10 個排程
2. 編輯後改為 8 個排程
3. 儲存後資料庫有 18 個排程項目（10 舊 + 8 新）
4. 再編輯一次，變成 26 個...

## 🐛 根本原因

### 原本的邏輯（有問題）：

```
SaveMode(mode) 
  ↓
if (mode.Id > 0)  // 更新現有模式
  ↓
1. UPDATE schedule_modes (更新模式資訊) ✅
2. DELETE FROM mode_schedule_mapping  ✅ (刪除關聯)
3. [缺少] DELETE FROM schedule_items  ❌ (沒有刪除舊排程!)
  ↓
SaveSchedulesForMode()
  ↓
4. INSERT INTO schedule_items (插入新排程) ✅
5. INSERT INTO mode_schedule_mapping (建立新關聯) ✅
```

**結果**：
- ✅ `mode_schedule_mapping` 正確更新
- ❌ `schedule_items` 累積舊資料，一直增長

## ✅ 修正後的邏輯

```
SaveMode(mode) 
  ↓
if (mode.Id > 0)  // 更新現有模式
  ↓
1. 取得此模式的所有 schedule_id
2. DELETE FROM mode_schedule_mapping (刪除關聯)
3. 檢查每個 schedule_id 是否還被其他模式使用
4. DELETE FROM schedule_items (刪除未被使用的排程項目) ✅ 新增!
  ↓
SaveSchedulesForMode()
  ↓
5. INSERT INTO schedule_items (插入新排程)
6. INSERT INTO mode_schedule_mapping (建立新關聯)
```

**改進**：
- ✅ 刪除不再使用的 `schedule_items`
- ✅ 保留被其他模式共用的排程項目
- ✅ 避免資料累積

## ⚠️ 注意事項

### 共用排程項目

如果未來實作「多個模式共用同一個排程項目」的功能，此邏輯已經處理：

```csharp
// 檢查此 schedule_id 是否還被其他模式使用
if (usageCount == 0)
{
	// 沒有其他模式使用，才刪除
	DELETE FROM schedule_items WHERE id = @scheduleId
}
```

只有**完全沒有模式使用的排程項目**才會被刪除。

### 效能考量

目前每個 schedule_id 都會檢查是否被其他模式使用。如果排程數量很大（例如 100+ 個），可以優化為：

```sql
-- 一次性刪除所有未被使用的排程
DELETE FROM schedule_items 
WHERE id IN (@scheduleIds)
AND id NOT IN (SELECT DISTINCT schedule_id FROM mode_schedule_mapping);
```

但目前的實作已經足夠，因為：
- 每個模式通常只有 10-20 個排程
- 在交易中執行，保證資料一致性
