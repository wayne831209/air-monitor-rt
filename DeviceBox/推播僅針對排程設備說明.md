# 推播僅針對排程設備功能說明

## 功能概述

推播通知系統已優化為**只針對有排程運行的設備**進行監控和推播，避免推播停機或非工作時間的設備異常。

## 運作邏輯

### 1. 排程判斷
系統會在背景監控時檢查每個工廠的排程狀態：
- 從當前排程模式（`currentMode`）中取得該工廠的所有排程
- 篩選出 `Enabled = true` 且當前時間在排程範圍內的排程
- 收集這些排程關聯的空壓機 `MachineNo`

### 2. 監控範圍
只有符合以下條件的空壓機才會被監控：
- ✅ 空壓機所屬的排程已啟用（`Enabled = true`）
- ✅ 當前時間在排程的時間範圍內（`IsInSchedule()` 回傳 `true`）
- ✅ 空壓機的 Modbus 連線正常

### 3. 推播內容
推播通知只包含有排程的設備：
- **溫度異常**：只推播有排程的空壓機
- **空壓異常**：只推播有排程的空壓機
- **設備警報**：只推播有排程的空壓機
- **設備故障**：只推播有排程的空壓機

## 技術實作

### GetScheduledCompressorIds() 方法
```csharp
private HashSet<int> GetScheduledCompressorIds(FactoryConfig factory)
{
	var scheduledIds = new HashSet<int>();

	if (currentMode == null || currentMode.Schedules == null)
		return scheduledIds;

	// 找出該工廠當前時間內有排程的所有空壓機
	var activeSchedules = currentMode.Schedules.Where(s =>
		s.FactoryId == factory.Id &&
		s.Enabled &&
		IsInSchedule(s)).ToList();

	foreach (var schedule in activeSchedules)
	{
		scheduledIds.Add(schedule.MachineNo);
	}

	return scheduledIds;
}
```

### MonitorAllDevicesInBackground() 方法修改
```csharp
// 取得該工廠當前有排程的空壓機 ID 集合
var scheduledCompressorIds = GetScheduledCompressorIds(factory);

// 如果沒有任何空壓機有排程，跳過此工廠
if (scheduledCompressorIds.Count == 0)
{
	System.Diagnostics.Debug.WriteLine($"[排程推播] {factory.Name} 沒有空壓機在排程時間內，跳過監控");
	continue;
}

// 取得該工廠的所有空壓機
var compressors = factory.GetDevicesByType(DeviceType.Compressor);

// 只保留有排程的空壓機
var scheduledCompressors = compressors.Where(c => scheduledCompressorIds.Contains(c.MachineNo)).ToList();

// 檢查空壓和溫度是否超限（只針對有排程的空壓機）
if (scheduledCompressors.Count > 0)
{
	// 建立有排程的設備名稱列表
	var deviceNames = scheduledCompressors.Select(c => c.Name).ToList();

	// ... 檢查超限邏輯
}

// 檢查每台有排程的空壓機的警報和故障狀態
foreach (var compressor in scheduledCompressors)
{
	// ... 檢查警報和故障
}
```

## 使用情境

### 情境 1：工作時間內
```
排程時間: 週一~週五 08:00-17:00
當前時間: 週三 10:00
結果: 推播所有異常（溫度、空壓、警報、故障）
```

### 情境 2：非工作時間
```
排程時間: 週一~週五 08:00-17:00
當前時間: 週三 22:00
結果: 不推播任何異常（設備不在排程時間內）
```

### 情境 3：假日
```
排程時間: 週一~週五 08:00-17:00
當前時間: 週六 10:00
結果: 不推播任何異常（設備不在排程時間內）
```

### 情境 4：部分設備有排程
```
工廠 A:
  - CO-32: 週一~週五 08:00-17:00 (有排程)
  - CO-35: 無排程
當前時間: 週三 10:00
結果: 只推播 CO-32 的異常，CO-35 不推播
```

### 情境 5：排程停用
```
工廠 A:
  - CO-32: 週一~週五 08:00-17:00 (Enabled = false)
當前時間: 週三 10:00
結果: 不推播 CO-32 的異常（排程已停用）
```

## Debug 訊息

啟用排程推播後，會輸出以下 Debug 訊息：

```
[排程推播] 其他場域_連棟1 當前有 3 台空壓機在排程時間內
[排程推播] 其他場域_連棟2 沒有空壓機在排程時間內，跳過監控
[推播延遲] 溫度異常開始追蹤: CO-32, CO-35
[推播延遲] 溫度異常已持續 2.1 分鐘，符合推播條件
[推播] 偵測到符合推播條件的異常:
  溫度異常: CO-32, CO-35
```

## 優點

1. **避免誤報**：不會推播非工作時間的異常
2. **減少干擾**：只關注正在運行的設備
3. **精準監控**：只推播真正需要關注的異常
4. **節省資源**：減少不必要的推播通知
5. **彈性調整**：透過排程設定控制監控範圍

## 注意事項

### 排程設定
- 必須在**模式選擇**介面中設定排程
- 排程必須啟用（`Enabled = true`）才會生效
- 排程時間範圍必須正確設定

### 推播條件
- 推播開關（`teams_enabled`）必須為 `true`
- Teams Webhook URL 必須設定
- 推播間隔時間（`notification_cooldown_minutes`）會影響推播頻率
- 超限延遲時間（`alarm_delay_minutes`）會影響推播時機

### 軟體重啟
- 重啟軟體後，會重新判斷當前時間的排程狀態
- 異常追蹤時間會重置

### 排程變更
- 修改排程後立即生效
- 無需重啟軟體

## 疑難排解

### 問題 1：推播沒有發送
**檢查項目**：
1. 推播開關是否啟用（`teams_enabled = true`）
2. Teams Webhook URL 是否正確
3. 當前時間是否在排程範圍內
4. 排程是否啟用（`Enabled = true`）
5. 設備是否連線正常

### 問題 2：推播包含非排程設備
**檢查項目**：
1. 確認該設備是否有排程設定
2. 確認排程時間範圍是否正確
3. 查看 Debug 訊息確認有幾台空壓機在排程時間內

### 問題 3：推播遺漏某些設備
**檢查項目**：
1. 確認該設備的排程是否啟用
2. 確認當前時間是否在排程範圍內
3. 確認設備的 `MachineNo` 是否與排程一致
4. 查看 Debug 訊息確認設備是否被識別

## 總結

推播僅針對排程設備的功能確保了監控系統的精準性和實用性，避免了非工作時間的誤報干擾，讓使用者能夠專注於真正需要關注的設備異常。
