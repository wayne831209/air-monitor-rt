# 場域隔離測試指南

## 問題描述
之前的實現中，兩個軟體實例共用同一個 `site.config` 檔案，導致：
- A 軟體在"鑄造廠"模式一
- B 軟體切換到"其他場域"模式二
- A 軟體的場域配置被 B 軟體覆蓋，導致錯誤同步

## 解決方案
使用 **Process ID** 來區分不同實例的配置檔案：
- 第一個實例：`site_1234.config` (PID=1234)
- 第二個實例：`site_5678.config` (PID=5678)

每個 Process 都有獨立的配置檔案，互不干擾。

## 修改內容

### 1. SiteManager.cs
```csharp
// 使用 Process ID 區分配置檔案
private static readonly string SiteConfigPath = Path.Combine(
	Application.StartupPath, 
	$"site_{System.Diagnostics.Process.GetCurrentProcess().Id}.config");
```

### 2. MainForm.cs OnFormClosing
```csharp
// 應用程式關閉時清理配置檔案
SiteManager.Instance.Cleanup();
```

### 3. 額外的場域驗證
在 `SyncService_ConfigUpdated` 中加入雙重檢查：
```csharp
if (e.SiteId != siteManager.CurrentSiteId)
{
	// 忽略其他場域的更新
	return;
}
```

## 測試步驟

### 測試一：相同場域同步 ✅
1. 開啟第一個 DeviceBox.exe，選擇"其他場域"，設為模式一
2. 開啟第二個 DeviceBox.exe，選擇"其他場域"
3. 在第二個軟體中切換到模式二
4. **預期結果**：第一個軟體在 5 秒內自動切換到模式二

### 測試二：不同場域隔離 ✅
1. 開啟第一個 DeviceBox.exe，選擇"鑄造廠"，設為模式一
2. 開啟第二個 DeviceBox.exe，選擇"其他場域"
3. 在第二個軟體中切換到模式二
4. **預期結果**：第一個軟體保持在模式一，**不受影響**

### 測試三：配置檔案隔離
1. 開啟兩個 DeviceBox.exe
2. 檢查執行目錄應該看到：
   ```
   site_12345.config  <- 第一個實例
   site_67890.config  <- 第二個實例
   ```
3. 關閉任一軟體，對應的配置檔案應該被自動刪除

### 異常情況檢查：
如果看到：

但此實例應該在"鑄造廠"，表示場域 ID 混淆了。

## SQL 診斷查詢

```sql
-- 檢查各場域的獨立狀態
SELECT 
	site_id,
	site_name,
	current_mode_id,
	config_version,
	last_updated_by,
	updated_at
FROM site_config
ORDER BY updated_at DESC;

-- 應該看到：
-- foundry | 鑄造廠 | 1 | 5  | DESKTOP-ABC | 2024-01-15 10:30:00
-- other   | 其他場域 | 2 | 4 | DESKTOP-ABC | 2024-01-15 10:35:00
```

## 預期效果

✅ **場域隔離**：不同場域的軟體實例互不影響  
✅ **同場域同步**：相同場域的軟體實例自動同步  
✅ **配置獨立**：每個 Process 有自己的 site_PID.config  
✅ **自動清理**：Process 結束時自動刪除配置檔案  

## 故障排除

### 問題：兩個實例還是互相影響
- 檢查 Debug 輸出的 PID 是否不同
- 檢查 `SiteConfigPath` 是否正確包含 Process ID
- 確認沒有其他程式碼還在使用舊的 `site.config`

### 問題：配置檔案沒有清理
- 檢查 `OnFormClosing` 是否被正確呼叫
- 手動刪除殘留的 `site_*.config` 檔案

### 問題：場域選擇每次都跳出
- 正常行為！因為配置檔案在關閉時被刪除
- 如果需要持久化場域選擇，需要使用全域配置檔案（但會回到原問題）
- 建議：為常用場域提供命令列參數啟動
