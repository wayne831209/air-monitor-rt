# 排程設定儲存到資料庫 - 修正完成

## ✅ 已完成的修改

### 1. 新增 SaveModeSchedulesToDatabase() 方法
- 位置：`ModeSelectForm.Database.cs`
- 功能：將模式的排程儲存到資料庫
- 特點：
  - 完整的診斷訊息
  - 錯誤處理和提示
  - 返回成功/失敗狀態

### 2. 修改 ScheduleSettingForm.cs
- 從呼叫 `SaveModeSchedules()` (XML版本)
- 改為呼叫 `SaveModeSchedulesToDatabase()` (資料庫版本)
- 增加診斷訊息

## 🎯 修正的問題

### 問題：
編輯排程後，變更沒有儲存到資料庫，只儲存到 XML

### 原因：
`ScheduleSettingForm` 在儲存時呼叫的 `SaveModeSchedules()` 方法還在使用舊的 XML 儲存邏輯

### 解決方案：
創建新的 `SaveModeSchedulesToDatabase()` 方法，直接呼叫 `ScheduleDatabase.SaveMode()`

#### 方法 C: 直接查詢資料庫
```sql
-- 查看模式的排程數量
SELECT 
	sm.id,
	sm.name,
	COUNT(msm.schedule_id) as schedule_count
FROM schedule_modes sm
LEFT JOIN mode_schedule_mapping msm ON sm.id = msm.mode_id
WHERE sm.id = 1  -- 替換成您的模式 ID
GROUP BY sm.id, sm.name;

-- 查看排程詳細內容
SELECT 
	si.id,
	si.factory_name,
	si.device_name,
	si.start_day,
	si.start_time,
	si.end_day,
	si.end_time,
	si.enabled
FROM schedule_items si
JOIN mode_schedule_mapping msm ON si.id = msm.schedule_id
WHERE msm.mode_id = 1  -- 替換成您的模式 ID
ORDER BY si.factory_name, si.device_name;
```

## 🔍 故障排除

### 問題 A: 輸出視窗沒有 [ScheduleSettingForm] 訊息
**原因**：可能沒有正確進入儲存流程
**解決**：
1. 確認排程設定視窗有 "儲存" 或 "確定" 按鈕
2. 確認點擊後有觸發儲存事件

### 問題 B: 看到 "Save result: False"
**原因**：資料庫儲存失敗
**查看**：
1. 尋找 `[ScheduleDatabase]` 開頭的錯誤訊息
2. 可能是 SQL 錯誤、權限問題或連線失敗

### 問題 C: 儲存成功但重新開啟後沒有變更
**可能原因**：
1. 載入時還在讀 XML 而不是資料庫
2. Mode ID 不正確

**解決**：
1. 確認 `LoadScheduleItems()` 方法使用 `GetModeById()` (已改用資料庫版本)
2. 確認 `_modeId` 參數正確傳入

### 問題 D: 出現 "無法連接資料庫" 錯誤
**解決**：
1. 檢查資料庫連線 (使用啟動測試工具的 "1. 測試資料庫連線")
2. 確認 `config.xml` 中的資料庫設定正確

## 📊 完整的儲存流程

```
1. 使用者編輯排程
   ↓
2. 點擊 "儲存" 按鈕
   ↓
3. ScheduleSettingForm 收集變更
   ↓
4. 建立 ScheduleMode 物件
   ↓
5. 呼叫 SaveModeSchedulesToDatabase(mode)
   ↓
6. 初始化 Config 和 ScheduleDatabase
   ↓
7. 呼叫 ScheduleDatabase.SaveMode(mode)
   ↓
8. 開始資料庫事務
   ↓
9. 更新 schedule_modes 表
   ↓
10. 刪除舊的 mode_schedule_mapping
   ↓
11. 刪除舊的 schedule_items (如果沒有其他模式使用)
   ↓
12. 插入新的 schedule_items
   ↓
13. 插入新的 mode_schedule_mapping
   ↓
14. 提交事務
   ↓
15. 返回成功
```
