# 資料庫問題診斷步驟

## 問題：資料沒有進入資料庫

### 診斷步驟：

## 步驟 1: 啟動診斷工具

1. 執行程式（F5）
2. 在啟動畫面點擊 "🔧 進階診斷工具"

## 步驟 2: 檢查資料表結構

點擊 "檢查資料表結構" 按鈕，確認：
- ✓ schedule_modes 資料表存在
- ✓ schedule_items 資料表存在  
- ✓ mode_schedule_mapping 資料表存在

**如果資料表不存在**：
→ 請執行 `DeviceBox\Database\create_schedule_tables.sql` 腳本

## 步驟 3: 查看現有資料

點擊 "查看 Modes 資料" 和 "查看 Schedules 資料" 按鈕
→ 檢查資料庫是否真的是空的

## 步驟 4: 測試插入

點擊 "測試插入資料" 按鈕
→ 這會直接呼叫 ScheduleDatabase.SaveMode() 方法

**如果測試插入成功**：
→ 表示資料庫連線和寫入功能正常
→ 問題可能出在主程式的呼叫流程

**如果測試插入失敗**：
→ 查看錯誤訊息
→ 可能是資料表結構問題或權限問題

## 步驟 5: 檢查主程式流程

如果測試插入成功，但主程式還是沒資料：

1. 點擊 "✓ 啟動主程式"
2. 打開 Visual Studio 的 "輸出" 視窗 (Ctrl+Alt+O)
3. 選擇 "偵錯" 分頁
4. 執行以下操作並觀察輸出：
   - 開啟模式選擇視窗
   - 新增一個模式
   - 儲存

### 預期看到的偵錯訊息：

```
[ModeSelectForm] Loaded X modes from database
[ScheduleDatabase] Mode 'XXX' saved successfully
[ModeSelectForm] Saved X modes to database
```

## 常見問題：

### 問題 A: 資料表不存在
**解決方法**：執行 SQL 腳本建立資料表

### 問題 B: 權限不足
**解決方法**：確認 config.xml 中的資料庫使用者有 INSERT/UPDATE/DELETE 權限

### 問題 C: ID 衝突
**症狀**：SaveMode 失敗，錯誤訊息包含 "Duplicate entry"
**解決方法**：
1. 點擊診斷工具的 "清空所有資料"
2. 讓程式重新建立資料

### 問題 D: 連線逾時
**症狀**：錯誤訊息包含 "Timeout"
**解決方法**：檢查資料庫伺服器是否可連線

## 除錯技巧：

### 在 ModeSelectForm.cs 的 SaveModes() 方法中加入中斷點：

```csharp
private void SaveModes()
{
	try
	{
		if (_scheduleDb == null)  // <- 在這裡設中斷點
		{
			var config = new Config();
			if (config.LoadConfig())
			{
				_scheduleDb = config.GetScheduleDatabase();
			}
		}

		if (_scheduleDb != null)  // <- 在這裡設中斷點
		{
			foreach (var mode in _modes)  // <- 在這裡設中斷點
			{
				_scheduleDb.SaveMode(mode);  // <- 在這裡設中斷點
			}
		}
	}
	catch (Exception ex)
	{
		MessageBox.Show($"Save modes failed: {ex.Message}", "Error", MessageBoxButtons.OK, MessageBoxIcon.Error);
	}
}
```

### 檢查重點：

1. `_scheduleDb` 是否為 null？
   → 如果是，表示資料庫連線沒建立

2. `_modes` 列表是否有資料？
   → 如果沒有，表示沒有模式可儲存

3. `SaveMode(mode)` 是否被執行？
   → 如果沒執行到這裡，檢查前面的條件

4. `SaveMode(mode)` 的回傳值？
   → 如果返回 false，查看 Debug 輸出視窗的錯誤訊息

## 完整測試流程：

1. ✅ 啟動診斷工具
2. ✅ 檢查資料表結構 → 確認都存在
3. ✅ 測試插入 → 確認能寫入
4. ✅ 查看資料 → 確認有測試資料
5. ✅ 啟動主程式
6. ✅ 開啟模式管理
7. ✅ 新增/編輯模式
8. ✅ 回到診斷工具查看資料
